# UNDO — Vertical Slice Specification

## Purpose

The vertical slice proves that the complete UNDO experience works when the validated causal mechanics are combined with near-final presentation.

It is not a demo of the whole story and must not spoil Record 0.

## Entry gate

Do not begin the vertical slice until:
- Prototype A is technically stable,
- Prototype B passes its Consequence Persistence comprehension/interest gate,
- Prototype C proves deterministic NPC reactions,
- reset/debug tooling is reliable enough for level iteration.

## Target playtime

First-time play target:
**approximately 25–35 minutes**

Experienced replay may be significantly shorter.

## Slice location

A contiguous archive/security transfer area spanning a late B1 / early B2-feeling section.

The slice should feel like part of the real Repository 4 facility rather than a standalone test chamber.

Suggested spatial sequence:

```
Staff Office Threshold
→ Security Corridor
→ Badge / Transfer Desk
→ Staff Gate
→ Service Lift Antechamber
→ Exit Lift
```

## Mechanics included

The slice must include:

1. basic event suppression,
2. object-level Review Mode,
3. Residual Exposure,
4. deterministic NPC routine observation,
5. route redirect,
6. Consequence Persistence,
7. suppression release timing,
8. at least one present-time NPC reaction generated by a contradiction,
9. RESTORE CURRENT RECORD,
10. one maintained-correction capacity only.

Do **not** include:
- second correction slot,
- masked historical events,
- institutional AUTHORIZATION paradox as a major mechanic,
- Record 0,
- 39-second narrative reveal,
- final ending logic.

The slice should prove depth without exposing all campaign escalation.

## Suggested slice puzzle flow

### VS01 — Staff Threshold

Teaching beat:
- worker closes door,
- player discovers Residual Exposure,
- suppresses close,
- learns that the player does not directly operate the door.

Short and nearly frictionless.

### VS02 — Patrol Redirect

Guard follows a routine.

A correctable door/lock state determines whether the guard turns down the normal corridor or enters a staff route.

Player changes condition before a defined route decision point.

Goal:
teach indirect NPC movement.

### VS03 — Badge Persistence

Core slice centerpiece.

Routine:
- badge rests on desk,
- guard takes badge,
- scans access point,
- door unlocks,
- guard proceeds.

Player suppresses badge take after authorization/unlock.

Required realization:
- badge returns,
- useful consequence remains.

This is the signature moment.

### VS04 — Missing Badge Reaction

Returned/contradictory badge state becomes visible to an actor at an authored check point.

Reaction redirects the guard or staff member into a service area and generates a new door/open event.

Goal:
prove present-time reactions can be understood.

### VS05 — Let It Close

Player maintains a door correction long enough for an actor to cross, then releases it.

The actor is placed into a condition that triggers a service/emergency response opening the final route.

Goal:
prove release is a deliberate puzzle verb.

## Narrative content

The vertical slice includes only light, non-spoiler narrative.

It may establish:
- Repository 4 is being migrated/closed,
- Han Jaemin is on a late/final shift,
- the facility is old and layered,
- some historical sections are restricted.

It should **not** establish:
- Seojin's death details,
- Jaemin's 39-second delay,
- Record 0's true meaning.

A small incidental appearance of the name 윤서진 in old facility material is optional only if it does not turn the slice into a story trailer.

## Final presentation target

Unlike prototypes, the vertical slice should use representative final quality for:
- one modern office/archive kit,
- one older security/service kit,
- representative character presentation,
- Residual Exposure,
- Review Mode,
- sound language,
- signage,
- in-world computer UI,
- lighting,
- pause/settings baseline,
- subtitles/accessibility baseline.

Not every production asset family must be complete.

## Art requirement

The slice must prove the visual thesis:

> aging Korean public-record facility + institutional realism + photographic double exposure.

If the slice begins to resemble:
- a futuristic lab,
- generic sci-fi corridors,
- an abandoned horror hospital,
- a neon puzzle game,
- an AI dashboard,

presentation direction is failing even if the mechanic works.

## Audio requirement

The slice must prove:
- footsteps convey routine,
- door/scanner/elevator states have readable functional sounds,
- important off-screen actions remain legible,
- correction sounds are restrained and tactile,
- puzzle success requires no fanfare,
- score does not obscure gameplay information.

## UI requirement

The slice must prove:
- normal HUD can remain nearly absent,
- first-time players notice correctable events,
- Review can be used without a global timeline,
- maintained correction can be understood without a permanent 1/1 HUD,
- system menus remain usable without modern SaaS styling.

## Accessibility baseline

Slice settings must include at least:
- subtitle on/off and size baseline,
- correction visibility strength,
- reduced/disabled motion blur,
- FOV,
- key remapping or at minimum architecture supporting it,
- hold/toggle alternative for Review if implemented as hold,
- separate effects/music/dialogue volumes.

Exact release settings list can expand later.

## Performance target

Initial PC slice goal:
- stable 60 FPS target at 1080p on a reasonable mid-range development target,
- no puzzle logic tied to frame rate,
- no visible long stalls during correction/state changes,
- deterministic behavior at varying rendering frame rates.

Exact minimum/recommended hardware is not locked until profiling on real target machines.

## Reliability target

Before greenlighting full content production:
- full slice can be completed repeatedly from a clean save,
- RESTORE CURRENT RECORD works in every slice puzzle,
- no causal state corruption after expected correction/release paths,
- debug ledger explains all gameplay-relevant state,
- automated domain tests remain green,
- headless scene/content validation is green.

## Playtest questions

Observe rather than leading testers.

Key questions after play:
- What did Undo actually do?
- Why did the badge come back while the door stayed unlocked?
- How did you know where the guard would go?
- What did releasing a correction do?
- Did any state change feel like a bug rather than a consequence of a rule?
- Did the interface tell you too much, too little, or at the wrong time?
- Did any visual element feel like generic futuristic/AI UI?
- Did waiting feel excessive?

## Greenlight criteria

Proceed to full campaign production only if the slice demonstrates:

### Mechanical
- causal rules remain correct,
- signature persistence is understandable,
- NPC reactions are predictable enough to plan,
- release timing adds meaningful reasoning,
- reset is dependable.

### Experiential
- players want to test more causal combinations,
- confusion is localized and fixable through presentation/level design,
- the lack of direct manipulation feels intentional rather than broken.

### Production
- level graybox-to-art workflow is manageable,
- state bugs are diagnosable,
- content authoring does not require excessive bespoke code,
- performance is within reasonable scope,
- source control/Codex workflow remains practical.

If a major category fails, revise before multiplying content.
